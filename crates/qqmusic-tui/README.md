# qqmusic-tui

[go-musicfox](https://github.com/go-musicfox/go-musicfox) 风格的 QQ 音乐终端播放器，基于 [`qqmusic-api`](../qqmusic-api)、ratatui 与 crossterm。

- **界面与播放分离**：TUI 只负责浏览和发指令，播放由后台守护进程完成，两者通过系统本地 IPC 通信（Unix domain socket / Windows 命名管道）。按 `q` 退出界面后音乐继续播放，再次打开会自动连上。
- **系统媒体控制**：macOS Now Playing / 媒体键、Windows SMTC、Linux MPRIS（纯 Rust 的 zbus，无需 libdbus）。
- **音质选择**：无损 / 高品质 / 标准，取不到时自动降级；切换后当前歌曲从原位置按新音质重新加载。
- **推荐续播**：从猜你喜欢或雷达推荐开始播放后，当前列表的最后一首播放结束时，后台获取下一轮新歌并去重、继续播放，退出界面后仍会继续。雷达会沿页码加载，一轮结束后重新请求；随机模式播放完尚未播放的歌曲后获取下一轮，单曲循环保持不变。连续 3 批请求失败或没有新歌时停止，可稍后重新播放重试。
- 猜你喜欢、雷达推荐、我喜欢的音乐、我的歌单、推荐歌单、排行榜、新歌、搜索（单曲 / 歌手 / 专辑 / 歌单，带补全与历史）、从歌曲进入专辑和歌手、歌词视图（含翻译）、喜欢 / 取消喜欢、QQ / 微信 / QQ 音乐 App 扫码登录、四种播放模式。
- **大列表按需加载**：搜索结果、歌单、专辑、喜欢列表先显示第一批，光标接近末尾时继续加载；状态行写明「已加载 N / 共 M」。单个页面最多保留 2000 条，达到后会注明没有全部加载。

## 使用

```sh
cargo install --path crates/qqmusic-tui  # 安装后的命令名为 qqm
qqm              # 打开界面（自动在后台启动播放进程）
qqm ctl toggle   # 控制后台播放：toggle | play | pause | next | prev | stop | status | quit
qqm daemon       # 前台运行播放进程（调试用）
```

数据（凭证、设备信息、配置、日志）默认存放在系统数据目录下的 `qqm`（Linux 为 `~/.local/share/qqm`），可用环境变量 `QQM_HOME` 指定。其中 `config.json` 保存音质、音量、播放模式，以及切歌 / 暂停时的渐入渐出时长 `fade_ms`（默认 400，设为 0 关闭）。Linux 需要 ALSA 开发库（`libasound2-dev` / `alsa-lib-devel`）。

### 界面

宽度 ≥ 100 列时左侧常驻导航，≥ 120 列时右侧再加一栏歌词或队列（`w` 切换 / 关闭）；更窄时只留主内容，首页就是菜单。列表是单列表格，行数随终端高度变化；选中项用 `›`、正在播放用 `♪`、队列里确定的下一首用 `»` 标出。底部三行是播放栏：状态与歌曲、进度、提示或通知。

`Tab` / `Shift+Tab` 在导航、内容、侧栏之间切换焦点，有焦点的区域标题前有 `▍`。弹窗打开时按键只交给弹窗，`Esc` 先关弹窗再返回上一级。按 `?` 查看全部快捷键（小窗口里可滚动）。

| 按键 | 作用 |
| --- | --- |
| `j` `k` / `g` `G` / `Ctrl+d` `Ctrl+u` | 上下移动 / 首尾 / 翻页（任何宽度下含义相同） |
| `Enter` `n` | 进入；在歌曲上是**播放并替换队列** |
| `l` `→` | 进入；在歌曲上只打开操作菜单 |
| `h` `←` `b` `Esc` | 返回上一级 |
| `/` | 搜索；搜索框里 `Tab` / `Ctrl+T` 切换类型，`↑` `↓` 选补全或历史，`Ctrl+X` 清除历史 |
| `t` | 搜索结果页切换类型（各类型保留自己的位置与已加载内容） |
| `A` / `a` | 下一首播放 / 追加到队尾 |
| `o` | 歌曲操作菜单：播放、入队、喜欢、查看专辑、查看歌手 |
| `c` | 打开播放队列；在队列里定位到当前歌曲 |
| `d` / `J` `K` / `D` | 队列：移除 / 下移上移 / 清空（需确认） |
| `Space` `[` `]` `,` `.` `-` `=` | 播放暂停、切歌、快退快进 5 秒、音量 |
| `m` / `v` | 播放模式 / 最高音质 |
| `f` / `F` | 喜欢当前播放 / 选中的歌曲 |
| `L` | 歌词视图：`j` `k` 手动滚动，`Enter` 跳到选中行，`z` 恢复跟随，`t` 翻译开关，`r` 重新加载 |
| `r` | 刷新当前页；「加载更多」失败时只重试那一页 |
| `e` / `x` | 通知与错误列表 / 关闭底部的错误提示 |
| `q` / `Q` | 退出界面（音乐继续，重新打开会接上） / 退出并停止后台 |

### 播放与入队

- **播放并替换队列**（`Enter`）：用当前页**已加载**的歌曲替换整个队列，从选中的那首开始。列表还没加载完时提示会写明「播放已加载的 N 首（共 M 首）」，不会当成整张歌单。
- **下一首播放**（`A`）：插到当前歌曲之后，不打断正在播放的歌。连按多次时后加的先播；随机模式下这些歌也会先于随机挑选播放。
- **追加到队尾**（`a`）：不改变正在播放的歌；队列为空时会开始播放。

入队、移除这类操作先显示「正在…」，后台确认后才显示完成，失败会如实报告。播放栏右下角的「接下来」来自后台的播放计划；随机模式下没有安排好的下一首时显示「随机挑选」。同一首歌可以重复入队，队列操作按条目而不是按下标生效，其他界面改过队列后不会删错歌。

### 出错与恢复

错误会留在底栏直到按 `x` 关闭，同时记入 `e` 打开的列表，不会被普通提示顶掉。提示里带恢复办法：

- **登录失效**：到「账号」重新登录。账号页区分「登录有效」「暂时无法确认」（网络问题，不算退出登录）和「登录已过期」。
- **无法播放**（会员、版权、地区）：自动换下一首；连续 10 首都不行就停止。VIP 标记只是提示，是否能播以实际取链接的结果为准。
- **网络或服务暂时失败**：页面保留已有内容，按 `r` 重试；播放连续 3 首失败后停止。下载中途断开时从断点重新加载一次，再失败才换下一首。
- **本地问题**（音频设备、凭证读写）：见 `daemon.log`。凭证保存失败时不会提示登录成功，退出登录删不掉凭证时登录状态保持不变。

暂停之后不会被自动恢复：加载失败、换歌、切换音质、推荐补歌都保持暂停，只有主动恢复才出声。

### 断线

界面与后台断开时顶栏显示「后台未连接」并自动重连。期间切歌、入队、删除、暂停等操作**直接拒绝并提示**，不会攒到重连后一起执行；音量、播放模式、音质只保留最新的设置，重连后生效；登录变更在重连后同步。重连后以后台当前的队列和状态为准。

### 升级

升级后请先退出旧界面并运行 `qqm ctl quit` 关闭旧后台，再打开新版 `qqm`，使后台功能更新生效。新界面连到旧后台时会提示后台版本较旧：基本播放仍可用，但操作确认、队列排序不可用。IPC 协议的版本号见 `protocol::PROTOCOL_VERSION`：新增字段都有默认值，新增的指令和事件只在双方都声明支持后使用。

### Windows 媒体卡片显示「未知应用」

Windows 根据应用身份显示 SMTC 卡片的应用名称与图标。便携 exe 的歌曲信息和控制按钮可以正常工作，但未注册身份时应用名称可能为「未知应用」。本项目的 MSVC 构建已嵌入身份清单，可选注册步骤见 [`windows/README.md`](windows/README.md)。注册后显示为「QQ 音乐 TUI」。

## 作为库使用

| feature | 内容 |
| --- | --- |
| （无） | 协议 `protocol`、IPC 客户端 `ipc`、配置与路径 |
| `player` | 播放引擎 `player` 与守护进程 `daemon` |
| `media-controls` | 系统媒体控制 `media`（隐含 `player`） |
| `tui` | 终端界面 `tui` |

默认开启 `tui` + `media-controls`。只想控制一个正在运行的播放进程：

```toml
qqmusic-tui = { version = "0.0.5", default-features = false }
```

```rust,no_run
use qqmusic_tui::ipc::IpcClient;
use qqmusic_tui::paths::Paths;
use qqmusic_tui::protocol::Command;

# async fn demo() -> std::io::Result<()> {
let mut client = IpcClient::connect(&Paths::new()?).await?;
client.send(&Command::Next).await?;
# Ok(()) }
```

也可以用 `player::spawn` 把播放引擎直接嵌入自己的程序。IPC 协议是按行分隔的 JSON（见 `protocol::Command` / `protocol::Event`），任何语言都能接入。
